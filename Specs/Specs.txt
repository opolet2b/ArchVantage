This mockup describes a User Interface for the creation or modification of AI Agents.
LIST OF AGENTS SECTION
At the left handside is a list of agents. It lists the name of existing agents.
• The « Plus » sign next to the « Agent » title allows to create a new agent. The new agent can be created in the middle section called « Configuration ».
• If the user clicks on the name of an agent, its configuration is displayed in the « Configuration » Section.
• If the user clicks on the name of an agent while a agent is being created or modified in the « configuration » section then the system should ask the user if he wants to save the configuration. Upon confirmation, the system must save the configuration.
• The three dots at the left of the agent’s name in the list of agent open a contextual menu. For the time being the only options available are « »rename » and  delete ». 
• If the user selects « rename » then he is prompted to modify the name of the agent. 
• If the user presses « delete » then the systems asks for confirmation. Upon confirmation the agent and its configuration are deleted from the system and removed from storage.
CONFIGURATION SECTION
This central section allows the user to configure the agent.
• When the user clicks on the “Plus” sign next to the “Agent” Title in the “List of agents” section, the system checks if an agent is being created or modified. If so, the user is prompted to save the current agent and upon confirmation of the user, the configuration of the currently modified agent is saved. Once this is done or if no agent was under creation or modification, “Configuration” and “Preview” sections are emptied letting the user create a new agent.
• The “Save” button allows to save the configuration of the agent. When the user clicks “Save”:
• If it is a new agent that does not have a name,  the user is prompted to enter a name for the agent and upon confirmation the configuration of the agent is saved and the agent appears in the “List of Agents”
• If it is a existing agent that has been modified, then the configuration of this agent is saved under its name.
• The “What should this agent do?” sub-section allows the user to enter his expectations of what the agent should do. 
• Once the user has validated his prompt then the system generates a more extensive and complete system prompt.
• The “Three dots” next to the “What should this agent do?” display a popup with the system prompt generated by the system. The user can review and update and save this system prompt using this popup.
• The “What should this agent avoid?” sub-section allows the user to enter his constraints about what the agent should NOT do. 
• Once the user has validated his prompt then the system generates a more extensive and complete system prompt.
• The “Three dots” next to the “What should this agent avoid?” display a popup with the system prompt generated by the system. The user can review and update and save this system prompt using this popup.
• The “Knowledge base » sub-section allows the user to drag and drop a file to add it o the agent’s knowledge base (RAG). 
• Once the file has been drop, it is automatically « ragged »: vectorized and embedded into the vector Database of the system. During this vectorization phase, a progress bar should be displayed similar to the process used when the user adds a new file using the paperclip in the main chatbot window.
• Once a file has been vectorized it is added as an icon to the sub-section « Knowledge base ».
• When a file has been added to the knowledge base, the agent must « remember » that file because it is part of its knowledge base and any rag activity of the agent should focus on the files of its knowledge base. As a consequence each agent has its own knowledge base.
• The user should be able to delete a file that has been added to the knowledge base. If possible there should be a « delete » option in a contextual menu that would appear when the user right-clicks on the icon of a file in the « knowledge base » sub-section. If not possible an alternative option can be implemented. When the user requests to delete a file he is prompted for confirmation. Upon confirmation, the file is deleted and disappears from the knowledge base and its embeddings are deleted.
• The “Skills” sub-section
• The “Skills” sub-section allows the user to select tools for the agent.
• The “three-dots” next to the “tools” title open a popup that lists all available skills. This popup is like an “Appstore”, with lists of tools represented with icons and a description of what they do. The user can select a tool and add it to the tools of the agent.
• Once a tool has been added, its icon is displayed in the “Tools” sub-section. 
•  The user should be able to delete a tool. If possible there should be a « delete » option in a contextual menu that would appear when the user right-clicks on the icon of a tool in the « Tools » sub-section. If not possible an alternative option can be implemented. When the user requests to delete a tool he is prompted for confirmation. Upon confirmation, the tool is deleted and disappears from the “Tools” section.
Preview Section
The “Preview” section allows a live preview of the agent in action.
* The “Chat with the agent…” prompt allows the user to enter a request for the agent to do something
* When the user validates his request, the system runs and expectfully will initiate the agent that will start its action.
* When the agent executes, it will first consider the user query, which will be displayed in the “Input” box.
* Then it will “think” and build his plan to address the user query. This plan / thought will appear in the “Thought” box.
* Then it will decide and execute a set of actions. This actions will appear in the “Action” box
* It will get some feedback from the action and analyze this feedback. This will appear in the “Observation” box
* Finally the agent will provide its response to the request. It will appear in the “Response” box
* Each box (Input, Thought, Action, Observation, Response) has a “three dots” next to it. Clicking on the “three dots” will open a popup that allows the user to browse the full content.
